# MCP Python SDK 快速上手指南

> 本文档面向首次接触 MCP Python SDK 的开发者，介绍核心接口函数和初级使用场景，每个场景都附带完整的交互示例。
>
> **什么是 MCP？** 用一句话来说：MCP（Model Context Protocol）就是"给 AI 装插件的标准协议"。就像浏览器通过 HTTP 访问网页一样，LLM（大语言模型）通过 MCP 来调用外部工具、读取数据、获取提示模板。你用 MCP SDK 写一个"服务器"，就相当于给 AI 开发了一个插件——AI 可以在对话中自动发现并使用你的功能。

## 一、核心接口函数一览

### 服务端（Server 端）

| 接口 / 装饰器 | 说明 | 所在模块 |
|---|---|---|
| `MCPServer(name, ...)` | 创建高层 MCP 服务器实例 | `mcp.server.mcpserver` |
| `@mcp.tool()` | 注册一个 Tool（工具），LLM 可调用 | `MCPServer` 方法 |
| `@mcp.resource(uri)` | 注册一个 Resource（资源），支持静态 URI 和模板 URI | `MCPServer` 方法 |
| `@mcp.prompt()` | 注册一个 Prompt（提示模板） | `MCPServer` 方法 |
| `mcp.run(transport=...)` | 启动服务器（stdio / sse / streamable-http） | `MCPServer` 方法 |

### 客户端（Client 端）

| 接口 / 函数 | 说明 | 所在模块 |
|---|---|---|
| `Client(server)` | 高层客户端，支持内存直连、URL 连接 | `mcp.client.client` |
| `ClientSession(read, write)` | 底层客户端 Session，用于 stdio/SSE/HTTP 传输 | `mcp.client.session` |
| `stdio_client(params)` | 通过子进程 stdio 管道连接 MCP 服务器 | `mcp.client.stdio` |
| `streamable_http_client(url)` | 通过 HTTP+SSE 连接 MCP 服务器 | `mcp.client.streamable_http` |
| `sse_client(url)` | 通过 SSE 连接 MCP 服务器 | `mcp.client.sse` |

### 常用类型

| 类型 | 说明 |
|---|---|
| `StdioServerParameters` | stdio 传输参数（command、args、env） |
| `CallToolResult` | 工具调用结果 |
| `TextContent` | 文本内容块 |
| `ImageContent` | 图片内容块 |
| `Image` | 高层图片封装（自动处理 base64） |

## 三、场景 1：创建一个最简 Tool 服务器

### 🎯 业务场景

> **故事**：你是公司新来的开发，老板说："我们想让 Claude 能直接调用我们内部的功能，比如先做个最简单的——让 AI 能'复读'用户说的话。你先搞个 demo 出来，下午给我看看效果。"
>
> **直观理解**：这就像你在微信里加了一个"复读机器人"——你发什么，它回什么。但这里的区别是，这个机器人注册在了 MCP 协议上，所以 Claude、GPT 等任何支持 MCP 的 AI 都能自动发现并调用它。
>
> **这个场景解决什么问题？** 帮你理解 MCP 开发的最小闭环：写一个 Python 函数 → 用装饰器注册为 Tool → 启动服务器 → AI 就能调用了。整个过程只需要 **5 行代码**。

### 代码

```python
# echo_server.py
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("Echo Server")

@mcp.tool()
def echo(text: str) -> str:
    """Echo back the input text"""
    return text

if __name__ == "__main__":
    mcp.run()  # 默认 stdio 传输
```

### 交互示例

假设你已经写好了上面的 `echo_server.py`，下面是从启动到看到效果的完整过程：

```
# 第 1 步：用 MCP 自带的调试工具启动服务器（会自动打开一个可视化界面）
uv run mcp dev echo_server.py

# 第 2 步：浏览器会打开 MCP Inspector 界面
# 你会看到左侧有三个标签页：Tools / Resources / Prompts

# 第 3 步：点击 "Tools" 标签页 → 看到 "echo" 工具（自动从你的函数名提取）
# 工具描述显示为 "Echo back the input text"（自动从 docstring 提取）

# 第 4 步：在参数栏输入：{"text": "Hello, MCP!"}
# 第 5 步：点击 "Run" 按钮
# 第 6 步：下方显示返回结果：
#   [TextContent(type="text", text="Hello, MCP!")]

# 🎉 成功！你的第一个 MCP 工具跑起来了！
# 现在任何支持 MCP 的 AI 客户端（如 Claude Desktop）都可以自动发现并使用这个工具。
```

> **给老板看的一句话总结**：我们用 5 行 Python 代码，就让 AI 拥有了调用我们自定义功能的能力。以后只要加更多 `@mcp.tool()` 函数，AI 的能力就会自动扩展。

**要点**：
- `@mcp.tool()` 自动从函数签名提取参数 schema
- 函数的 docstring 会作为工具描述
- 返回值会自动包装成 `TextContent`

## 四、场景 2：定义 Resource（静态资源 & 模板资源）

### 🎯 业务场景

> **故事**：老板很满意 demo，继续提需求："光能调用函数不够，我们还希望 AI 能读取一些配置信息和用户数据。比如 AI 在回答问题时，能自动读到我们 App 当前的设置（深色模式、语言是中文），也能根据用户 ID 查到用户资料。"
>
> **直观理解**：如果说 Tool 是"AI 的手"（能做事），那 Resource 就是"AI 的眼睛"（能看到数据）。
> - **静态资源**就像办公室里贴在墙上的公告栏——内容固定，谁来都看同一张。比如系统配置。
> - **模板资源**就像图书馆的索引系统——你说"帮我查第 001 号用户"，它会根据编号去找对应的资料。比如根据用户 ID 查用户信息。
>
> **这个场景解决什么问题？** 让 AI 能"看到"你系统中的数据，而不需要你把数据复制粘贴到对话里。AI 会自动列出有哪些资源可读，然后按需读取。

### 代码

```python
# resource_server.py
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("Resource Server")

# 静态资源：固定 URI
@mcp.resource("config://app-settings")
def get_settings() -> str:
    """Return application settings"""
    return '{"theme": "dark", "language": "zh-CN", "version": "1.0"}'

# 模板资源：URI 中含有参数占位符
@mcp.resource("users://{user_id}/profile")
def get_user_profile(user_id: str) -> str:
    """Return user profile by ID"""
    profiles = {
        "001": '{"name": "张三", "role": "admin"}',
        "002": '{"name": "李四", "role": "user"}',
    }
    return profiles.get(user_id, '{"error": "user not found"}')

if __name__ == "__main__":
    mcp.run()
```

### 交互示例

想象以下对话场景，AI 在背后自动读取资源：

```
# === 场景 A：AI 读取系统配置 ===
# 用户问："我们 App 当前用的什么主题？"
# AI 内部动作：哦，有个 config://app-settings 资源，让我读一下

await client.read_resource("config://app-settings")
# 返回: ReadResourceResult(contents=[TextResourceContents(
#     uri="config://app-settings",
#     text='{"theme": "dark", "language": "zh-CN", "version": "1.0"}'
# )])

# AI 回答用户："当前 App 使用的是深色主题，语言设置为中文，版本号 1.0。"

# === 场景 B：AI 根据用户 ID 查资料 ===
# 用户问："帮我查一下 001 号用户是谁？"
# AI 内部动作：有个 users://{user_id}/profile 资源模板，我把 001 填进去

await client.read_resource("users://001/profile")
# 返回: ReadResourceResult(contents=[TextResourceContents(
#     uri="users://001/profile",
#     text='{"name": "张三", "role": "admin"}'
# )])

# AI 回答用户："001 号用户是张三，角色是管理员。"

# === 场景 C：AI 自动发现有哪些资源可用 ===
# AI 初始化时会先"看看有什么资源可以读"

await client.list_resource_templates()
# 返回: ListResourceTemplatesResult(resource_templates=[
#     ResourceTemplate(uri_template="users://{user_id}/profile", name="get_user_profile")
# ])

# AI 由此知道："我可以查任意用户的资料，只要提供 user_id 就行"
```

> **给老板看的一句话总结**：现在 AI 不仅能做事，还能看到我们系统里的数据了——配置信息、用户资料等，AI 都能按需自动读取。

**要点**：
- 静态资源使用固定 URI，如 `"config://app-settings"`
- 模板资源使用 `{param}` 占位符，如 `"users://{user_id}/profile"`
- 模板参数从函数参数自动提取

## 五、场景 3：定义 Prompt 模板

### 🎯 业务场景

> **故事**：团队里的产品经理说："我们每天都要让 AI 审查代码、翻译文档，但每次都要手动写提示词好麻烦。能不能做成模板？我选个模板、填个参数就能用？"
>
> **直观理解**：Prompt 模板就像公司的"公文模板"。比如你们有一套标准的代码审查流程——"请审查以下 Python 代码并提出改进建议：[代码贴这里]"。与其每次手敲这段话，不如做成模板，用的时候只需要把代码贴进去就行。
>
> **Tool vs Resource vs Prompt 的区别**：
> - **Tool（工具）**= AI 的手 → 做事情（调函数、写数据）
> - **Resource（资源）**= AI 的眼 → 看数据（读配置、查用户）
> - **Prompt（提示）**= AI 的说明书 → 告诉 AI 怎么做事（审查代码的步骤、翻译的风格要求）

### 代码

```python
# prompt_server.py
from mcp.server.mcpserver import MCPServer
from mcp.server.mcpserver.prompts import base

mcp = MCPServer("Prompt Server")

# 简单文本 prompt
@mcp.prompt()
def code_review(code: str, language: str = "python") -> str:
    """Review code and provide suggestions"""
    return f"请审查以下 {language} 代码并提出改进建议：\n\n```{language}\n{code}\n```"

# 返回消息列表的 prompt（支持多轮对话）
@mcp.prompt()
def translate(text: str, target_language: str = "英文") -> list[base.Message]:
    """Translate text to target language"""
    return [
        base.UserMessage(f"请将以下文本翻译为{target_language}："),
        base.UserMessage(text),
        base.AssistantMessage(f"好的，我来将文本翻译为{target_language}。"),
    ]

if __name__ == "__main__":
    mcp.run()
```

### 交互示例

想象一个代码审查的完整流程：

```
# === 第 1 步：AI 客户端先看看有哪些模板可用 ===
await client.list_prompts()
# 返回: ListPromptsResult(prompts=[
#     Prompt(name="code_review", arguments=[
#         PromptArgument(name="code", required=True),        ← 必填：要审查的代码
#         PromptArgument(name="language", required=False),    ← 可选：编程语言，默认 python
#     ]),
#     Prompt(name="translate", arguments=[...]),
# ])
# AI 知道了："我有两个提示模板——代码审查和翻译"

# === 第 2 步：用户说"帮我审查这段代码"，AI 使用 code_review 模板 ===
await client.get_prompt("code_review", {"code": "print('hello')", "language": "python"})
# 返回: GetPromptResult(messages=[
#     PromptMessage(role="user", content=TextContent(
#         text="请审查以下 python 代码并提出改进建议：\n\n```python\nprint('hello')\n```"
#     ))
# ])
# AI 拿到了一段精心组织的提示词，然后用这段话去调用 LLM 完成审查

# === 第 3 步：用户说"把这段话翻译成英文"，AI 使用 translate 模板 ===
await client.get_prompt("translate", {"text": "你好世界", "target_language": "英文"})
# 返回一个多轮对话消息列表：
#   UserMessage: "请将以下文本翻译为英文："
#   UserMessage: "你好世界"
#   AssistantMessage: "好的，我来将文本翻译为英文。"
# 这种多轮格式可以引导 AI 进入"翻译助手"的角色
```

> **给老板看的一句话总结**：我们把常用的 AI 指令（代码审查、翻译等）做成了可复用的模板，全公司统一使用，不用每次手写提示词了。

## 六、场景 4：使用 Client 连接并调用 Server

### 🎯 业务场景

> **故事**：开发写好了几个 Tool，想在本地快速验证一下"AI 调用我的工具，结果对不对"。不想部署服务器、不想配网络，就想在一个 Python 脚本里跑通全流程。
>
> **直观理解**：这就像在你自己电脑上开了一个"沙盒"——服务器和客户端都在同一个进程里，通过内存直接通信，不走任何网络。你可以把它理解为"单机版微信"：自己给自己发消息，瞬间到达，非常适合写测试和做 demo。
>
> **这个场景解决什么问题？** 不需要启动任何外部服务，一个 Python 文件里就能完成：定义工具 → 模拟 AI 调用 → 看到结果。开发效率极高。

### 代码

```python
# test_server.py
import anyio
from mcp.client.client import Client
from mcp.server.mcpserver import MCPServer

# 创建服务器
mcp = MCPServer("Calculator")

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers"""
    return a + b

@mcp.tool()
def multiply(a: int, b: int) -> int:
    """Multiply two numbers"""
    return a * b

@mcp.resource("math://pi")
def get_pi() -> str:
    return "3.14159265358979"

async def main():
    # Client(server) 内存直连，无需传输层
    async with Client(mcp) as client:
        # 列出工具
        tools = await client.list_tools()
        print("可用工具：")
        for tool in tools.tools:
            print(f"  - {tool.name}: {tool.description}")

        # 调用工具
        result = await client.call_tool("add", {"a": 3, "b": 5})
        print(f"\n3 + 5 = {result.content[0].text}")  # "8"

        result = await client.call_tool("multiply", {"a": 4, "b": 7})
        print(f"4 × 7 = {result.content[0].text}")  # "28"

        # 读取资源
        resource = await client.read_resource("math://pi")
        print(f"\nπ = {resource.contents[0].text}")

anyio.run(main)
```

### 交互输出

运行 `python test_server.py` 后，终端会打印：

```
可用工具：                               ← AI 发现了两个可用工具
  - add: Add two numbers                 ← 加法工具
  - multiply: Multiply two numbers       ← 乘法工具

3 + 5 = 8                                ← AI 调用 add 工具，结果正确 ✅
4 × 7 = 28                               ← AI 调用 multiply 工具，结果正确 ✅

π = 3.14159265358979                     ← AI 读取了 math://pi 资源
```

> **关键观察**：整个过程没有启动任何服务器，没有用到网络，完全在一个 Python 进程内完成。这是做单元测试和快速验证的最佳方式。

**要点**：
- `Client(mcp_server)` 直接传入服务器实例即可内存直连
- 异步上下文管理器自动处理初始化和清理
- 最适合单元测试和快速验证

## 七、场景 5：用 stdio 传输运行 Server + Client

### 🎯 业务场景

> **故事**：老板说："Demo 效果不错，现在我想把这个工具接到 Claude Desktop 上。我在 Claude 里直接说'帮我算个数'，Claude 就能调用我们的计算器工具。怎么做？"
>
> **直观理解**：这就像你在手机上安装了一个 App 的"快捷指令"。Claude Desktop 会以子进程的方式启动你的 Python 服务器脚本，然后通过"标准输入/输出管道"（stdin/stdout）跟它通信——就像两个人通过一根管道传纸条：Claude 从管道的一头塞进去"帮我算 2*(3+4)"，你的服务器从另一头收到后算出 14，再塞回去。
>
> **什么时候用 stdio？**
> - ✅ Claude Desktop 本地集成（官方推荐方式）
> - ✅ 本地命令行工具
> - ✅ 不需要网络、零配置
> - ❌ 不适合远程调用（因为要在同一台机器上）

### 服务器代码

```python
# my_server.py
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("My Tool Server")

@mcp.tool()
def greet(name: str) -> str:
    """Greet someone by name"""
    return f"你好，{name}！欢迎使用 MCP！"

@mcp.tool()
def calculate(expression: str) -> str:
    """Evaluate a math expression (safe subset)"""
    allowed = set("0123456789+-*/.(). ")
    if all(c in allowed for c in expression):
        return str(eval(expression))
    return "不支持的表达式"

if __name__ == "__main__":
    mcp.run()  # 默认 stdio 传输
```

### 客户端代码

```python
# my_client.py
import anyio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    # 定义服务器启动参数
    server_params = StdioServerParameters(
        command="python",
        args=["my_server.py"],
    )

    # 建立 stdio 连接
    async with stdio_client(server_params) as (read_stream, write_stream):
        async with ClientSession(read_stream, write_stream) as session:
            # 初始化协议握手
            await session.initialize()

            # 列出工具
            tools_result = await session.list_tools()
            print("服务器提供的工具：")
            for tool in tools_result.tools:
                print(f"  [{tool.name}] {tool.description}")

            # 调用工具
            result = await session.call_tool("greet", {"name": "小明"})
            print(f"\n调用 greet: {result.content[0].text}")

            result = await session.call_tool("calculate", {"expression": "2 * (3 + 4)"})
            print(f"调用 calculate: {result.content[0].text}")

anyio.run(main)
```

### 交互输出

在终端运行 `python my_client.py`，会看到：

```
服务器提供的工具：                             ← 客户端自动发现了服务器的能力
  [greet] Greet someone by name               ← 打招呼工具
  [calculate] Evaluate a math expression      ← 计算器工具

调用 greet: 你好，小明！欢迎使用 MCP！         ← AI 调用了打招呼工具 ✅
调用 calculate: 14                            ← 2*(3+4)=14，计算正确 ✅
```

**完整的交互时序**（帮你理解底层发生了什么）：

```
客户端 (my_client.py)                    服务器 (my_server.py，作为子进程)
    │                                         │
    │──── 启动子进程 ─────────────────────────→│  客户端用 StdioServerParameters 启动服务器
    │                                         │
    │──── initialize() ──────────────────────→│  协议握手："你好，我是客户端"
    │←─── 服务器信息 ─────────────────────────│  "你好，我是 My Tool Server，支持 MCP 1.0"
    │                                         │
    │──── list_tools() ──────────────────────→│  "你有什么工具？"
    │←─── [greet, calculate] ────────────────│  "我有打招呼和计算两个工具"
    │                                         │
    │──── call_tool("greet", {name:"小明"}) ─→│  "帮我调用 greet，参数是小明"
    │←─── "你好，小明！" ────────────────────│  服务器执行函数，返回结果
    │                                         │
    │──── call_tool("calculate", ...) ───────→│  "帮我算 2*(3+4)"
    │←─── "14" ──────────────────────────────│  计算完毕，返回 14
    │                                         │
    │──── [退出，子进程自动关闭] ──────────────→│
```

> **给老板看的一句话总结**：现在 Claude Desktop 可以直接调用我们的工具了。用户在 Claude 里说"帮我算个数"，Claude 会自动找到我们的计算器，算好了直接回复用户。

**要点**：
- `StdioServerParameters` 指定服务器进程的启动命令
- `stdio_client()` 管理子进程的生命周期
- `session.initialize()` 必须在任何操作前调用

## 八、场景 6：用 Streamable HTTP 传输运行 Server + Client

### 🎯 业务场景

> **故事**：老板又有新需求了："本地跑是没问题，但我们想把 AI 工具部署到云服务器上，让团队里所有人（甚至是手机上的 AI 客户端）都能远程调用。就像调用 REST API 一样。"
>
> **直观理解**：如果 stdio 是"两个人面对面传纸条"，那 Streamable HTTP 就是"打电话"——你可以在任何地方拨通服务器的号码（URL），说出你的请求，对方执行后把结果告诉你。而且这个电话支持"实时语音"（SSE 流式推送），服务器可以边干活边给你播报进度。
>
> **什么时候用 HTTP？**
> - ✅ 部署到云服务器，多人远程调用
> - ✅ 集成到 Web 应用、移动端
> - ✅ 需要实时流式推送（如进度条）
> - ✅ 需要负载均衡、水平扩展
> - ❌ 比 stdio 复杂一点点（需要配置地址和端口）

### 服务器代码

```python
# http_server.py
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("HTTP Tool Server")

@mcp.tool()
def search(query: str, max_results: int = 5) -> str:
    """Search for information"""
    # 模拟搜索
    return f"搜索 '{query}' 的前 {max_results} 条结果：\n1. 结果一\n2. 结果二"

if __name__ == "__main__":
    mcp.run(
        transport="streamable-http",
        host="127.0.0.1",
        port=8000,
    )
```

### 客户端代码

```python
# http_client.py
import anyio
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client

async def main():
    async with streamable_http_client("http://127.0.0.1:8000/mcp") as (
        read_stream,
        write_stream,
    ):
        async with ClientSession(read_stream, write_stream) as session:
            await session.initialize()

            # 列出并调用工具
            tools = await session.list_tools()
            for tool in tools.tools:
                print(f"发现工具: {tool.name}")

            result = await session.call_tool(
                "search", {"query": "MCP 协议", "max_results": 3}
            )
            print(f"\n搜索结果:\n{result.content[0].text}")

anyio.run(main)
```

### 交互流程

需要打开两个终端窗口，模拟"服务器在云上运行，客户端在本地远程调用"的场景：

```
# ===== 终端 1：启动服务器（模拟部署到云上） =====
$ python http_server.py
INFO:     Uvicorn running on http://127.0.0.1:8000    ← 服务器启动，监听 8000 端口
# 此时服务器就像一个 REST API 一样在等待请求

# ===== 终端 2：运行客户端（模拟远程 AI 应用） =====
$ python http_client.py
发现工具: search                                      ← 客户端通过 HTTP 发现了工具

搜索结果:                                             ← 调用工具，通过 HTTP 传输参数和结果
搜索 'MCP 协议' 的前 3 条结果：
1. 结果一
2. 结果二
```

**底层发生了什么**（HTTP 请求/响应）：

```
客户端                                    服务器 (http://127.0.0.1:8000)
  │                                           │
  │── POST /mcp (initialize) ───────────────→│  建立 MCP 会话
  │←── 200 OK {server_info: "HTTP Tool"} ───│
  │                                           │
  │── POST /mcp (list_tools) ───────────────→│  "你有什么工具？"
  │←── 200 OK [{name: "search", ...}] ──────│  返回工具列表
  │                                           │
  │── POST /mcp (call_tool: search) ────────→│  "搜索 MCP 协议"
  │←── 200 OK "搜索结果..." ────────────────│  返回搜索结果
  │                                           │
  │── DELETE /mcp (close session) ──────────→│  关闭会话
```

> **给老板看的一句话总结**：我们的 AI 工具现在可以部署到云上了，团队任何人、任何设备都能远程调用，就像使用普通的 Web API 一样。

## 九、场景 7：结构化输出（Structured Output）

### 🎯 业务场景

> **故事**：后端团队提了个需求："AI 调用天气查询工具，返回的结果能不能是结构化的 JSON？我们前端需要把温度、湿度分别显示在不同的 UI 组件里。如果只返回一段文字'北京今天 22.5 度'，前端还得自己解析，太麻烦了。"
>
> **直观理解**：想象两种快递方式——
> - **普通模式**（文本输出）：快递员口头告诉你"你的快递有一本书、两支笔、三个本子"——你得自己记住，还可能听错。
> - **结构化模式**（Structured Output）：快递员给你一张清单，上面写着 `{书: 1, 笔: 2, 本子: 3}`——清清楚楚，程序可以直接读取每个字段。
>
> MCP 的结构化输出让工具同时返回两份数据：
> - **文本版**（给 AI/人类看）：`"北京: 22.5°C，湿度45%，晴天"`
> - **JSON 版**（给程序用）：`{"city": "北京", "temperature": 22.5, "humidity": 45.0, "condition": "晴"}`

### 代码

```python
# structured_server.py
from pydantic import BaseModel, Field
from mcp.server.mcpserver import MCPServer
from mcp.client.client import Client
import anyio

mcp = MCPServer("Weather Server")

class WeatherData(BaseModel):
    city: str = Field(description="城市名称")
    temperature: float = Field(description="温度（摄氏度）")
    humidity: float = Field(description="湿度百分比")
    condition: str = Field(description="天气状况")

@mcp.tool()
def get_weather(city: str) -> WeatherData:
    """Get weather information for a city"""
    # 模拟天气数据
    weather_db = {
        "北京": WeatherData(city="北京", temperature=22.5, humidity=45.0, condition="晴"),
        "上海": WeatherData(city="上海", temperature=25.0, humidity=78.0, condition="多云"),
    }
    return weather_db.get(
        city,
        WeatherData(city=city, temperature=20.0, humidity=50.0, condition="未知"),
    )

async def main():
    async with Client(mcp) as client:
        # 列出工具 - 注意 output_schema 字段
        tools = await client.list_tools()
        for tool in tools.tools:
            print(f"工具: {tool.name}")
            print(f"输出 Schema: {tool.output_schema}")

        # 调用工具
        result = await client.call_tool("get_weather", {"city": "北京"})

        # 文本内容（给 LLM 用）
        print(f"\n文本结果: {result.content[0].text}")

        # 结构化内容（给程序用）
        print(f"结构化结果: {result.structured_content}")
        # {"city": "北京", "temperature": 22.5, "humidity": 45.0, "condition": "晴"}

anyio.run(main)
```

### 交互输出

运行后可以看到两份数据同时返回：

```
工具: get_weather
输出 Schema: {'properties': {'city': ..., 'temperature': ..., 'humidity': ..., 'condition': ...}, 'type': 'object'}
# ↑ AI 客户端可以提前知道输出的 JSON 结构，用于 UI 渲染或数据校验

文本结果: city='北京' temperature=22.5 humidity=45.0 condition='晴'
# ↑ 这份给 AI 看：AI 读到后可以跟用户说"北京今天 22.5 度，天气晴朗"

结构化结果: {'city': '北京', 'temperature': 22.5, 'humidity': 45.0, 'condition': '晴'}
# ↑ 这份给程序用：前端可以直接取 result["temperature"] 显示在温度计组件里
```

**端到端的实际应用场景**：

```
用户在手机 App 上问："今天北京天气怎么样？"
         │
         ▼
AI 客户端 ──→ 调用 get_weather("北京") ──→ MCP 服务器
         │                                      │
         │                                      ▼
         │                          返回: content + structured_content
         │
         ▼
AI 客户端收到两份数据：
  ├── content（文本）→ 交给 LLM 生成自然语言回复
  │     "北京今天天气晴朗，气温 22.5°C，比较舒适，湿度 45%。"
  │
  └── structured_content（JSON）→ 交给前端 UI 组件
        ┌─────────────┐
        │ 🌤️ 北京      │
        │ 22.5°C  晴   │
        │ 湿度: 45%    │
        └─────────────┘
```

> **给老板看的一句话总结**：AI 工具现在能同时返回"人话"和"机器话"——AI 用文本跟用户聊天，前端用 JSON 渲染 UI，一份数据两用。

**要点**：
- 返回 Pydantic `BaseModel` 会自动生成 `output_schema`
- `result.content` 包含文本表示（给 LLM 读取）
- `result.structured_content` 包含结构化 JSON（给程序使用）
- 支持的类型：`BaseModel`、`TypedDict`、`dataclass`、`dict`、原始类型

## 十、快速上手要点总结

### 三步创建服务器

```python
from mcp.server.mcpserver import MCPServer

# 1. 创建实例
mcp = MCPServer("My Server")

# 2. 注册功能（tool / resource / prompt）
@mcp.tool()
def my_tool(param: str) -> str:
    return f"result: {param}"

# 3. 启动
mcp.run()  # stdio（默认）
# mcp.run(transport="streamable-http")  # HTTP
```

### 三步使用客户端

```python
# 方式 A：内存直连（测试用）
async with Client(mcp) as client:
    result = await client.call_tool("my_tool", {"param": "hello"})

# 方式 B：stdio 传输
async with stdio_client(StdioServerParameters(command="python", args=["server.py"])) as (r, w):
    async with ClientSession(r, w) as session:
        await session.initialize()
        result = await session.call_tool("my_tool", {"param": "hello"})

# 方式 C：HTTP 传输
async with streamable_http_client("http://localhost:8000/mcp") as (r, w):
    async with ClientSession(r, w) as session:
        await session.initialize()
        result = await session.call_tool("my_tool", {"param": "hello"})
```

### 关键记忆点

1. **`MCPServer`** 是唯一需要记住的服务端类
2. **三个装饰器**：`@mcp.tool()` / `@mcp.resource(uri)` / `@mcp.prompt()`
3. **Client** 支持内存直连（传 MCPServer）和远程连接（传 URL）
4. **stdio** 传输用于 Claude Desktop，**HTTP** 传输用于 Web 服务
5. 函数签名自动转换为参数 schema，docstring 自动成为描述
