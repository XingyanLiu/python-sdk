## 一、场景 1：低层 Server API —— 完全控制请求处理

### 🎯 业务场景

> **故事**：你的 AI 数据分析平台已经用 `MCPServer`（高层 API）快速搭建了 30 多个工具。但架构师提出几个高层 API 搞不定的需求：
> 1. 工具的输入 schema 需要根据用户角色动态生成（管理员看到更多字段）
> 2. 工具列表需要分页（有 200+ 工具，一次性返回太大）
> 3. 需要在每个请求的入口加一层自定义日志和计费逻辑
>
> **直观理解**：`MCPServer` 就像"自动挡汽车"——简单好开，但你不能精确控制每一次换挡。低层 `Server` API 就像"手动挡赛车"——你可以精确控制引擎的每一个细节，但需要更多操作技巧。
>
> 高层 `MCPServer`（装饰器）：写个函数 → 自动生成 schema → 自动处理调用 → 自动返回结果
> 低层 `Server`（回调函数）：手动定义 schema → 手动分发请求 → 手动构造响应
>
> **什么时候从高层降到低层？**
> - ✅ 需要动态 schema（根据上下文变化）
> - ✅ 需要分页返回
> - ✅ 需要自定义中间件逻辑（日志、计费、限流）
> - ❌ 只是简单的工具/资源/提示 → 用高层 API 就够了

### 代码

```python
import asyncio
import mcp.server.stdio
from mcp import types
from mcp.server import Server
from mcp.server.context import ServerRequestContext

# 创建低层 Server
server = Server("advanced-server")

# 手动定义工具列表
async def handle_list_tools(
    ctx: ServerRequestContext,
    params: types.PaginatedRequestParams | None,
) -> types.ListToolsResult:
    return types.ListToolsResult(
        tools=[
            types.Tool(
                name="analyze",
                description="Analyze data with custom schema",
                input_schema={
                    "type": "object",
                    "properties": {
                        "data": {"type": "array", "items": {"type": "number"}},
                        "method": {
                            "type": "string",
                            "enum": ["mean", "median", "std"],
                        },
                    },
                    "required": ["data", "method"],
                },
                # 手动定义输出 schema
                output_schema={
                    "type": "object",
                    "properties": {
                        "result": {"type": "number"},
                        "method": {"type": "string"},
                        "count": {"type": "integer"},
                    },
                    "required": ["result", "method", "count"],
                },
            )
        ]
    )

# 手动处理工具调用
async def handle_call_tool(
    ctx: ServerRequestContext,
    params: types.CallToolRequestParams,
) -> types.CallToolResult:
    if params.name == "analyze":
        data = params.arguments["data"]
        method = params.arguments["method"]

        import statistics
        if method == "mean":
            result = statistics.mean(data)
        elif method == "median":
            result = statistics.median(data)
        elif method == "std":
            result = statistics.stdev(data) if len(data) > 1 else 0
        else:
            return types.CallToolResult(
                content=[types.TextContent(type="text", text=f"Unknown method: {method}")],
                is_error=True,
            )

        structured = {"result": result, "method": method, "count": len(data)}
        return types.CallToolResult(
            content=[types.TextContent(type="text", text=f"{method}={result}")],
            structured_content=structured,
        )

    return types.CallToolResult(
        content=[types.TextContent(type="text", text=f"Unknown tool: {params.name}")],
        is_error=True,
    )

# 注册处理器
server = Server(
    "advanced-server",
    on_list_tools=handle_list_tools,
    on_call_tool=handle_call_tool,
)

async def run():
    async with mcp.server.stdio.stdio_server() as (read_stream, write_stream):
        await server.run(
            read_stream,
            write_stream,
            server.create_initialization_options(),
        )

if __name__ == "__main__":
    asyncio.run(run())
```

## 二、场景 2：OAuth 2.0 认证 —— 保护 MCP 服务

### 🎯 业务场景

> **故事**：你们的 MCP 服务部署到了公网上，任何人都能连。CTO 要求："必须加认证！只有公司内部系统、经过授权的合作伙伴才能调用我们的 AI 工具。用 OAuth 2.0，跟我们现有的统一登录系统对接。"
>
> **直观理解**：就像公司大楼的门禁系统——
> - **没有认证**：任何人都能进入大楼，使用会议室、打印机（很危险）
> - **有 OAuth 认证**：
>   1. 来访者先去前台（授权服务器）登记
>   2. 前台验证身份后发一张临时工牌（Access Token）
>   3. 来访者持工牌才能刷卡进入大楼（调用 MCP 工具）
>   4. 工牌有有效期，过期需要重新申请
>
> **涉及的标准协议**：
> - OAuth 2.0（授权框架）
> - RFC 9728（Protected Resource Metadata，资源服务器元数据发现）
> - RFC 8414（Authorization Server Metadata，授权服务器元数据发现）
>
> **解决的痛点**：MCP 服务上公网后的安全问题——未授权用户无法调用工具。

### 资源服务器代码

```python
from mcp.server.mcpserver import MCPServer
from mcp.server.auth.provider import AccessToken, TokenVerifier
from mcp.server.auth.settings import AuthSettings
from pydantic import AnyHttpUrl

class IntrospectionTokenVerifier(TokenVerifier):
    """通过令牌内省端点验证 token"""

    def __init__(self, introspection_url: str, client_id: str, client_secret: str):
        self.introspection_url = introspection_url
        self.client_id = client_id
        self.client_secret = client_secret

    async def verify_token(self, token: str) -> AccessToken | None:
        import httpx

        async with httpx.AsyncClient() as client:
            response = await client.post(
                self.introspection_url,
                data={"token": token},
                auth=(self.client_id, self.client_secret),
            )
            data = response.json()

            if not data.get("active"):
                return None

            return AccessToken(
                token=token,
                client_id=data.get("client_id", ""),
                scopes=data.get("scope", "").split(),
                expires_at=data.get("exp"),
            )

# 创建受保护的 MCP 服务器
mcp = MCPServer(
    "Protected API",
    token_verifier=IntrospectionTokenVerifier(
        introspection_url="https://auth.example.com/oauth/introspect",
        client_id="mcp-resource-server",
        client_secret="secret",
    ),
    auth=AuthSettings(
        issuer_url=AnyHttpUrl("https://auth.example.com"),
        resource_server_url=AnyHttpUrl("http://localhost:8000"),
        required_scopes=["mcp:tools"],
    ),
)

@mcp.tool()
def get_secret_data(key: str) -> str:
    """Get secret data (requires authentication)"""
    secrets = {"api_key": "sk-xxxx", "db_password": "pg-yyyy"}
    return secrets.get(key, "not found")

if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8000)
```

### 交互流程

一个未授权客户端从被拒绝到成功调用的完整过程：

```
# ===== 第 1 步：未授权请求 → 被拒绝 =====
POST http://localhost:8000/mcp
（没有带 Token）
→ 401 Unauthorized ❌
← WWW-Authenticate: Bearer resource_metadata="http://localhost:8000/.well-known/oauth-protected-resource"
   "你没有工牌！去前台登记。这是前台地址 ↑"

# ===== 第 2 步：客户端查看认证要求 =====
GET http://localhost:8000/.well-known/oauth-protected-resource
← {
    "resource": "http://localhost:8000",
    "authorization_servers": ["https://auth.example.com"],  ← "去这个授权服务器登记"
    "scopes_supported": ["mcp:tools"]                       ← "需要 mcp:tools 权限"
  }

# ===== 第 3 步：客户端走 OAuth 授权流程 =====
# 1) 客户端向授权服务器发起授权码请求（带 PKCE）
# 2) 用户在浏览器中登录并授权
# 3) 授权服务器返回 access_token
# 整个过程对终端用户来说就是：弹出登录页面 → 输入密码 → 点确认

# ===== 第 4 步：已授权请求 → 成功调用 =====
POST http://localhost:8000/mcp
Authorization: Bearer eyJhbGciOi...   ← 带上了"工牌"
→ 200 OK ✅（正常 MCP 通信）

# 此后所有 MCP 请求（list_tools、call_tool 等）都带上这个 Token
```

> **给老板看的一句话总结**：MCP 服务现在有了"门禁系统"——只有登录过的合法用户才能使用 AI 工具，外部人员无法访问。

## 三、场景 3：OAuth 客户端 —— 浏览器授权流程

### 🎯 业务场景

> **故事**：你做的 AI 客户端需要连接一个受 OAuth 保护的 MCP 服务器。用户第一次使用时要弹出浏览器让他登录授权，之后自动用缓存的 Token 连接。就像第一次用 GitHub 登录第三方应用——弹出授权页面，点"允许"，之后就不用再授权了。
>
> **直观理解**：想象你第一次用"微信登录"某个 App——
> - 第一次：App 弹出微信授权页面 → 你点"允许" → App 获得访问权限 → 把"通行证"存起来
> - 以后：App 直接用存好的"通行证"访问，不用再授权
> - 通行证过期：App 自动用"刷新令牌"换一个新的，你完全无感
>
> **SDK 自动处理的事情**（你不需要手写的）：
> 1. ✅ 发现 Protected Resource Metadata（RFC 9728）
> 2. ✅ 发现 Authorization Server Metadata（RFC 8414）
> 3. ✅ 动态客户端注册（RFC 7591）
> 4. ✅ 生成 PKCE Challenge（防中间人攻击）
> 5. ✅ 授权码换 Token
> 6. ✅ Token 刷新
> 7. ✅ Token 持久化存储

### 代码

```python
import anyio
import webbrowser
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client
from mcp.client.auth.oauth2 import OAuthClientProvider, TokenStorage
from mcp.shared.auth import OAuthClientMetadata, OAuthToken, OAuthClientInformationFull

class FileTokenStorage(TokenStorage):
    """将 token 持久化到文件"""

    def __init__(self, path: str = ".mcp_tokens.json"):
        self.path = path

    async def get_tokens(self) -> OAuthToken | None:
        import json
        try:
            with open(self.path) as f:
                data = json.load(f)
                return OAuthToken(**data.get("tokens", {})) if data.get("tokens") else None
        except FileNotFoundError:
            return None

    async def set_tokens(self, tokens: OAuthToken) -> None:
        import json
        data = {}
        try:
            with open(self.path) as f:
                data = json.load(f)
        except FileNotFoundError:
            pass
        data["tokens"] = tokens.model_dump()
        with open(self.path, "w") as f:
            json.dump(data, f)

    async def get_client_info(self) -> OAuthClientInformationFull | None:
        import json
        try:
            with open(self.path) as f:
                data = json.load(f)
                info = data.get("client_info")
                return OAuthClientInformationFull(**info) if info else None
        except FileNotFoundError:
            return None

    async def set_client_info(self, info: OAuthClientInformationFull) -> None:
        import json
        data = {}
        try:
            with open(self.path) as f:
                data = json.load(f)
        except FileNotFoundError:
            pass
        data["client_info"] = info.model_dump()
        with open(self.path, "w") as f:
            json.dump(data, f)

async def main():
    import httpx

    # 设置 OAuth 回调事件
    auth_code_event = anyio.Event()
    received_code = {"value": None}

    def redirect_handler(url: str) -> None:
        """浏览器打开授权 URL"""
        print(f"请在浏览器中授权: {url}")
        webbrowser.open(url)

    def callback_handler(code: str) -> None:
        """授权码回调"""
        received_code["value"] = code
        auth_code_event.set()

    # 创建 OAuth Provider
    oauth_provider = OAuthClientProvider(
        server_url="http://localhost:8000",
        client_metadata=OAuthClientMetadata(
            client_name="My MCP Client",
            redirect_uris=["http://localhost:3030/callback"],
            grant_types=["authorization_code", "refresh_token"],
            response_types=["code"],
        ),
        storage=FileTokenStorage(),
        redirect_handler=redirect_handler,
        callback_handler=callback_handler,
    )

    # 使用 OAuth 认证连接
    async with httpx.AsyncClient() as http_client:
        oauth_auth = oauth_provider.create_auth(http_client)

        async with streamable_http_client(
            "http://localhost:8000/mcp",
            httpx_client_factory=lambda: httpx.AsyncClient(auth=oauth_auth),
        ) as (read, write):
            async with ClientSession(read, write) as session:
                await session.initialize()
                print(f"已连接到: {session.initialize_result.server_info.name}")

                tools = await session.list_tools()
                for tool in tools.tools:
                    print(f"  工具: {tool.name}")

anyio.run(main)
```

## 四、场景 4：Task（长任务）—— 异步任务调度

### 🎯 业务场景

> **故事**：AI 团队做了一个"训练机器学习模型"的工具。训练需要 30 分钟到几小时。问题是 MCP 默认是"同步调用"——客户端调用工具后会一直等，HTTP 连接可能超时断开。需要一种"异步任务"模式：客户端发起训练 → 立即拿到任务 ID → 想看进度时再来查。
>
> **直观理解**：就像去洗衣店洗衣服——
> - **同步模式**（普通工具调用）：你把衣服交给店员，站在柜台前一直等到洗完才能走。如果要洗 2 小时，你就要站 2 小时。
> - **异步任务模式**（Task）：你把衣服交给店员，店员给你一张取衣单（任务 ID）。你可以去逛街、吃饭。想看进度时打电话问"我的衣服洗到哪了？"最后凭取衣单回来取。
>
> **什么时候用 Task？**
> - ✅ 执行时间超过 30 秒的操作（模型训练、大文件处理、批量数据迁移）
> - ✅ 客户端可能断线重连的场景
> - ✅ 需要随时查看进度/取消任务
> - ❌ 几秒钟就能完成的操作 → 用普通工具调用就好

### 服务端代码

```python
import asyncio
from mcp import types
from mcp.server import Server
from mcp.server.context import ServerRequestContext

server = Server("task-server")
server.experimental.enable_tasks()

async def handle_list_tools(
    ctx: ServerRequestContext,
    params: types.PaginatedRequestParams | None,
) -> types.ListToolsResult:
    return types.ListToolsResult(
        tools=[
            types.Tool(
                name="train_model",
                description="Train a machine learning model (long-running)",
                input_schema={
                    "type": "object",
                    "properties": {
                        "dataset": {"type": "string"},
                        "epochs": {"type": "integer", "default": 10},
                    },
                    "required": ["dataset"],
                },
                # 标记为必须以 Task 模式调用
                task_support=types.TASK_REQUIRED,
            )
        ]
    )

async def handle_call_tool(
    ctx: ServerRequestContext,
    params: types.CallToolRequestParams,
) -> types.CallToolResult:
    if params.name == "train_model":
        dataset = params.arguments["dataset"]
        epochs = params.arguments.get("epochs", 10)

        # 定义后台工作函数
        async def train_work(task):
            for epoch in range(epochs):
                await task.update_status(
                    message=f"训练中: epoch {epoch + 1}/{epochs}",
                    progress=epoch + 1,
                    total=epochs,
                )
                await asyncio.sleep(2)  # 模拟训练

            return types.CallToolResult(
                content=[types.TextContent(
                    type="text",
                    text=f"模型训练完成: {dataset}, {epochs} epochs, accuracy=0.95"
                )],
                structured_content={
                    "dataset": dataset,
                    "epochs": epochs,
                    "accuracy": 0.95,
                    "status": "completed",
                },
            )

        # 启动异步任务
        return await ctx.experimental.run_task(train_work)

    return types.CallToolResult(
        content=[types.TextContent(type="text", text="Unknown tool")],
        is_error=True,
    )

server = Server(
    "task-server",
    on_list_tools=handle_list_tools,
    on_call_tool=handle_call_tool,
)
server.experimental.enable_tasks()
```

## 五、场景 5：交互式 Task —— 任务中进行 Elicitation 和 Sampling

### 🎯 业务场景

> **故事**：运维团队做了一个"批量清理临时文件"的长任务。这个任务比较危险，执行过程中需要：
> 1. 先让用户确认"你确定要删除吗？"（Elicitation）
> 2. 确认后执行操作
> 3. 最后让 AI 生成一份操作报告（Sampling）
>
> 难点是：这个任务是异步的（Task 模式），但在异步执行过程中还需要"中途暂停、等用户输入"和"中途调用 AI"。
>
> **直观理解**：就像医生做手术——
> - 手术开始前：先让家属签署知情同意书（Elicitation - 用户确认）
> - 手术过程中：遇到意外情况，找专家远程会诊一下（Sampling - 调用 AI）
> - 手术完成后：生成手术报告（最终结果）
>
> 交互式 Task = 长时间异步任务 + 中途跟用户/AI 交互的能力。
>
> **解决的痛点**：长任务不再是"发射后不管"，可以在执行过程中随时跟用户和 AI 互动。

### 服务端代码

## 六、场景 6：ASGI 挂载 —— 集成到 Starlette/FastAPI

### 🎯 业务场景

>

## 八、场景 8：SSE 断线重连与 EventStore

### 🎯 业务场景

> **故事**：用户让 AI 执行一个需要 20 分钟的数据处理任务。处理到第 10 分钟时，用户的网络断了（比如手机从 WiFi 切到了 4G）。问题是：恢复网络后，前 10 分钟的进度通知全丢了吗？需要从头开始吗？
>
> **直观理解**：就像看直播——
> - **没有 EventStore**：你看直播时网断了 5 分钟，恢复后接着看当前画面，中间 5 分钟的内容永远错过了
> - **有 EventStore**：你看的是"直播回放"功能的直播，网断了恢复后，系统自动帮你补播中间漏掉的 5 分钟，然后接上当前进度
>
> EventStore 就是这个"直播回放系统"——把每一条通知都存起来，客户端断线重连后，告诉服务器"我最后看到的是第 42 条消息"，服务器就从第 43 条开始重新发送。
>
> **技术关键词**：SSE（Server-Sent Events）流 + `Last-Event-ID` 请求头 + EventStore 事件存储。
>
> **解决的痛点**：网络不稳定时不会丢失进度通知，断线重连后自动补发。

### 服务端代码

```python
import anyio
from mcp import types
from mcp.server import Server
from mcp.server.context import ServerRequestContext
from mcp.server.streamable_http import (
    StreamableHTTPServerTransport,
    EventStore,
    EventId,
    EventMessage,
)

class InMemoryEventStore(EventStore):
    """内存事件存储，用于 SSE 断线恢复"""

    def __init__(self):
        self._events: dict[str, list[tuple[EventId, EventMessage]]] = {}
        self._counter = 0

    async def store_event(
        self, stream_id: str, message: types.JSONRPCMessage | None
    ) -> EventId:
        self._counter += 1
        event_id = f"evt-{self._counter}"
        if stream_id not in self._events:
            self._events[stream_id] = []
        self._events[stream_id].append((event_id, EventMessage(
            event_id=event_id,
            message=message,
        )))
        return event_id

    async def replay_events_after(
        self, stream_id: str, last_event_id: str, max_events: int = 100
    ) -> list[EventMessage]:
        events = self._events.get(stream_id, [])
        found = False
        result = []
        for eid, emsg in events:
            if found:
                result.append(emsg)
                if len(result) >= max_events:
                    break
            if eid == last_event_id:
                found = True
        return result

server = Server("resilient-server")

async def handle_call_tool(
    ctx: ServerRequestContext,
    params: types.CallToolRequestParams,
) -> types.CallToolResult:
    if params.name == "long_process":
        total = 20
        for i in range(total):
            # 发送进度通知（会被 EventStore 记录）
            await ctx.session.send_log_message(
                level="info",
                data=f"步骤 {i + 1}/{total}",
                related_request_id=ctx.request_id,
            )
            await anyio.sleep(1)

            # 在关键节点关闭 SSE 流（触发客户端重连）
            if i == 9 and ctx.close_sse_stream:
                await ctx.close_sse_stream()

        return types.CallToolResult(
            content=[types.TextContent(type="text", text=f"完成 {total} 步")]
        )

# ... 注册处理器 ...

# 创建带 EventStore 的 Starlette 应用
from starlette.applications import Starlette
from starlette.routing import Mount

event_store = InMemoryEventStore()

app = Starlette(routes=[
    Mount("/", app=server.streamable_http_app(
        event_store=event_store,
        retry_interval=100,  # 100ms 重试间隔
    )),
])
```

## 九、场景 9：分页处理 —— 大数据集的资源列表

### 🎯 业务场景

> **故事**：你的 MCP 服务器注册了 200+ 个工具（大型企业 AI 平台常见）。如果一次性把 200 个工具的 schema 全返回给客户端，JSON 数据有好几 MB，网络传输慢、客户端解析也慢。需要"翻页"功能——每次只返回 10 个，客户端需要时再请求下一页。
>
> **直观理解**：就像 Google 搜索结果——
> - 搜出来 100 万条结果，不可能一页全显示
> - 第 1 页显示 10 条，页面底部有"下一页"按钮
> - 点"下一页"再显示 10 条
>
> MCP 的分页使用 `cursor`（游标）机制：每次返回结果时附带一个 `next_cursor`，客户端下次请求带上这个 cursor 就能拿到下一页。
>
> **解决的痛点**：大量工具/资源/提示不用一次性返回，按需分页加载，网络和内存压力都小。

### 服务端（低层 API）

```python
from mcp import types
from mcp.server import Server
from mcp.server.context import ServerRequestContext

server = Server("paginated-server")

# 模拟大数据集
ALL_TOOLS = [
    types.Tool(
        name=f"tool_{i}",
        description=f"Tool number {i}",
        input_schema={"type": "object", "properties": {}},
    )
    for i in range(100)
]

PAGE_SIZE = 10

async def handle_list_tools(
    ctx: ServerRequestContext,
    params: types.PaginatedRequestParams | None,
) -> types.ListToolsResult:
    cursor = params.cursor if params else None
    start = int(cursor) if cursor else 0

    page = ALL_TOOLS[start : start + PAGE_SIZE]
    next_start = start + PAGE_SIZE
    next_cursor = str(next_start) if next_start < len(ALL_TOOLS) else None

    return types.ListToolsResult(tools=page, next_cursor=next_cursor)

server = Server("paginated-server", on_list_tools=handle_list_tools)
```

### 客户端

```python
async def list_all_tools(session):
    """分页获取所有工具"""
    all_tools = []
    cursor = None

    while True:
        result = await session.list_tools(cursor=cursor)
        all_tools.extend(result.tools)
        print(f"获取了 {len(result.tools)} 个工具 (总计: {len(all_tools)})")

        if result.next_cursor:
            cursor = result.next_cursor
        else:
            break

    return all_tools

# 使用
tools = await list_all_tools(session)
print(f"共 {len(tools)} 个工具")
```

### 交互输出

客户端逐页加载 100 个工具的过程：

```
# 自动翻页加载，每页 10 个
获取了 10 个工具 (总计: 10)     ← 第 1 页：tool_0 ~ tool_9
获取了 10 个工具 (总计: 20)     ← 第 2 页：tool_10 ~ tool_19
获取了 10 个工具 (总计: 30)     ← 第 3 页...
...
获取了 10 个工具 (总计: 90)     ← 第 9 页
获取了 10 个工具 (总计: 100)    ← 第 10 页，next_cursor 为空，结束
共 100 个工具                   ← 全部加载完毕 ✅

# 对比不分页 vs 分页：
# 不分页：一次返回 100 个工具的 JSON → ~500KB，等 2 秒
# 分页：每次返回 10 个 → ~50KB，几十毫秒就响应
```

> **给老板看的一句话总结**：工具列表支持翻页了——200 个工具不用一次全加载，按需取 10 个，速度快 10 倍。

## 十、场景 10：自定义路由 —— 在 MCP 服务器中添加 HTTP 端点

### 🎯 业务场景

> **故事**：运维要求每个服务都有 `/health` 健康检查端点（K8s 存活探针用）；前端需要一个 `/webhook` 端点接收第三方回调；监控系统需要 `/metrics` 端点拉取指标。这些都不是 MCP 协议的一部分，但需要和 MCP 服务器共存在同一个进程和端口里。
>
> **直观理解**：MCP 服务器就像一个"专卖店"——只卖 MCP 协议的东西（工具、资源、提示）。`custom_route` 让你在专卖店旁边开了几个"小窗口"——卖点别的东西（HTTP 端点），但共用同一个门面（端口）。
>
> **解决的痛点**：不需要为健康检查、Webhook、监控指标等单独起一个 HTTP 服务器。

### 代码

```python
from mcp.server.mcpserver import MCPServer
from starlette.requests import Request
from starlette.responses import JSONResponse

mcp = MCPServer("Extended Server")

@mcp.tool()
def process(data: str) -> str:
    return f"processed: {data}"

# 自定义 HTTP 路由
@mcp.custom_route("/webhook", methods=["POST"])
async def handle_webhook(request: Request) -> JSONResponse:
    body = await request.json()
    # 处理 webhook
    return JSONResponse({"status": "received", "data": body})

@mcp.custom_route("/health", methods=["GET"])
async def health_check(request: Request) -> JSONResponse:
    tools = await mcp.list_tools()
    return JSONResponse({
        "status": "healthy",
        "server": mcp.name,
        "tools_count": len(tools),
    })

@mcp.custom_route("/metrics", methods=["GET"])
async def metrics(request: Request) -> JSONResponse:
    return JSONResponse({
        "requests_total": 42,
        "errors_total": 0,
        "uptime_seconds": 3600,
    })
```

### 交互

同一个端口（8000）上的不同端点：

```
# ===== MCP 通信（AI 客户端使用） =====
POST http://localhost:8000/mcp
→ 正常 MCP JSON-RPC 通信（工具调用、资源读取等）

# ===== 健康检查（K8s 存活探针使用） =====
GET http://localhost:8000/health
← {"status": "healthy", "server": "Extended Server", "tools_count": 1}
# K8s 看到 status=healthy 就知道服务正常 ✅

# ===== Webhook（第三方回调使用） =====
POST http://localhost:8000/webhook {"event": "data_updated"}
← {"status": "received", "data": {"event": "data_updated"}}
# 比如 GitHub 推送了代码更新通知，这里接收并处理

# ===== 监控指标（Prometheus 拉取使用） =====
GET http://localhost:8000/metrics
← {"requests_total": 42, "errors_total": 0, "uptime_seconds": 3600}
# 监控大屏上就能看到服务的运行状态

# 架构图：
# 端口 8000
# ├── /mcp       → MCP 协议端点（AI 工具调用）
# ├── /health    → 健康检查（运维探针）
# ├── /webhook   → Webhook 接收（第三方回调）
# └── /metrics   → 监控指标（Prometheus）
```

> **给老板看的一句话总结**：一个端口搞定所有事情——AI 工具、健康检查、Webhook、监控指标都在同一个服务里。

## 十一、场景 11：URL Elicitation —— OAuth 授权链路

### 🎯 业务场景

> **故事**：你做了一个"连接 GitHub"的工具——AI 帮用户在对话中说"帮我连接 GitHub"，工具需要弹出浏览器让用户在 GitHub 页面上点"授权"。还做了一个"支付"工具——AI 帮用户下单后，需要弹出支付页面让用户确认付款。
>
> **直观理解**：之前的 Elicitation（场景 3）是在 AI 对话内弹一个"表单"。URL Elicitation 是更进一步——直接弹出一个**网页**让用户在浏览器里操作。就像你在 App 里点"微信支付"，App 会跳转到微信的支付页面，操作完再跳回来。
>
> **解决的痛点**：需要跳转到第三方网站完成操作（OAuth 授权、支付、实名认证等）的场景。

### 代码

```python
import uuid
from mcp.server.mcpserver import MCPServer, Context
from mcp.shared.exceptions import UrlElicitationRequiredError
from mcp.types import ElicitRequestURLParams

mcp = MCPServer("Integration Service")

@mcp.tool()
async def connect_github(ctx: Context) -> str:
    """Connect to GitHub account"""
    elicitation_id = str(uuid.uuid4())

    # 方式 1：抛出异常（工具尚未执行完毕时要求用户先完成 URL 交互）
    raise UrlElicitationRequiredError([
        ElicitRequestURLParams(
            mode="url",
            message="请在浏览器中授权 GitHub 访问",
            url=f"https://github.com/login/oauth/authorize?client_id=xxx&state={elicitation_id}",
            elicitation_id=elicitation_id,
        )
    ])

@mcp.tool()
async def initiate_payment(amount: float, currency: str, ctx: Context) -> str:
    """Initiate a payment that requires user confirmation"""
    elicitation_id = str(uuid.uuid4())

    # 方式 2：使用 ctx.elicit_url（工具执行中途要求用户交互）
    result = await ctx.elicit_url(
        message=f"请确认支付 {amount} {currency}",
        url=f"https://payments.example.com/confirm?amount={amount}&currency={currency}&id={elicitation_id}",
        elicitation_id=elicitation_id,
    )

    if result.action == "accept":
        return f"支付已发起: {amount} {currency}"
    return "支付已取消"
```

### 客户端处理

```python
from mcp.types import ElicitResult

async def handle_elicitation(ctx, params):
    if params.mode == "url":
        print(f"请在浏览器中完成: {params.url}")
        import webbrowser
        webbrowser.open(params.url)
        # 等待用户完成操作...
        return ElicitResult(action="accept")
    # 表单模式
    return ElicitResult(action="accept", content={...})
```

## 十二、场景 12：结构化输出 + 低层 Server 的 output_schema

### 🎯 业务场景

> **故事**：你的金融团队做了一个"股票查询"工具。用低层 API 开发（因为需要动态 schema）。需要手动定义工具的输出格式——告诉客户端："这个工具返回的 JSON 里有 symbol、price、currency、change_pct 这些字段"。客户端（如交易 App）就能直接用 JSON 数据渲染实时行情卡片。
>
> **直观理解**：高层 API（`MCPServer`）会根据你的 Pydantic 模型自动生成 output_schema。但低层 API（`Server`）需要你手写 JSON Schema——就像高层 API 给你提供了"自动翻译"，低层 API 需要你"手写外语"，但你可以写得更精确。
>
> **解决的痛点**：低层 API 下也能提供结构化输出，客户端程序能提前知道返回数据的格式。

### 代码

```python
from mcp import types
from mcp.server import Server
from mcp.server.context import ServerRequestContext

server = Server("structured-output-server")

async def handle_list_tools(ctx, params):
    return types.ListToolsResult(
        tools=[
            types.Tool(
                name="get_stock_price",
                description="Get real-time stock price",
                input_schema={
                    "type": "object",
                    "properties": {
                        "symbol": {"type": "string", "description": "股票代码"},
                    },
                    "required": ["symbol"],
                },
                output_schema={
                    "type": "object",
                    "properties": {
                        "symbol": {"type": "string"},
                        "price": {"type": "number"},
                        "currency": {"type": "string"},
                        "change_pct": {"type": "number"},
                        "timestamp": {"type": "string", "format": "date-time"},
                    },
                    "required": ["symbol", "price", "currency"],
                },
            )
        ]
    )

async def handle_call_tool(ctx, params):
    if params.name == "get_stock_price":
        from datetime import datetime

        symbol = params.arguments["symbol"]
        data = {
            "symbol": symbol,
            "price": 150.25,
            "currency": "USD",
            "change_pct": 2.3,
            "timestamp": datetime.now().isoformat(),
        }

        return types.CallToolResult(
            # 文本内容给 LLM 读
            content=[types.TextContent(
                type="text",
                text=f"{symbol}: ${data['price']} ({data['change_pct']:+.1f}%)",
            )],
            # 结构化内容给程序用（会按 output_schema 验证）
            structured_content=data,
        )

server = Server(
    "structured-output-server",
    on_list_tools=handle_list_tools,
    on_call_tool=handle_call_tool,
)
```

## 十三、场景 13：CallToolResult 直接返回 + _meta 元数据

### 🎯 业务场景

> **故事**：电商团队做了一个"创建订单"工具。工具需要返回三层数据：
> 1. **文本**（给 AI 看）："订单已创建: ORD-12345, 总计 ¥199.8"
> 2. **结构化 JSON**（给前端程序用）：`{order_id, status, total}`
> 3. **内部元数据**（只给后台系统用，不能暴露给 AI）：仓库编号、内部 ID、预计发货日期
>
> 第三层很关键——你不想让 AI 知道"这个订单从北京仓库发货"（这是内部信息），但后台系统需要这个信息来做物流调度。
>
> **直观理解**：就像一个快递包裹——
> - **外面的标签**（text）：收件人看到的 "商品已发出"
> - **包裹里的商品**（structured_content）：实际的商品信息
> - **内部面单**（_meta）：仓库分拣员看到的内部路由信息，收件人看不到
>
> **解决的痛点**：工具可以附带"仅供程序内部使用"的元数据，不暴露给 LLM，保护内部信息。

### 代码

```python
from typing import Annotated
from pydantic import BaseModel
from mcp.server.mcpserver import MCPServer
from mcp.types import CallToolResult, TextContent

mcp = MCPServer("Meta Demo")

class OrderInfo(BaseModel):
    order_id: str
    status: str
    total: float

@mcp.tool()
def create_order(item: str, quantity: int) -> Annotated[CallToolResult, OrderInfo]:
    """Create a new order"""
    order_id = "ORD-12345"
    total = quantity * 99.9

    return CallToolResult(
        # LLM 看到的文本
        content=[TextContent(type="text", text=f"订单已创建: {order_id}, 总计 ¥{total}")],
        # 结构化数据
        structured_content={
            "order_id": order_id,
            "status": "pending",
            "total": total,
        },
        # 隐藏元数据（不发送给 LLM，但客户端应用可以读取）
        _meta={
            "internal_id": "INT-98765",
            "warehouse": "WH-BEIJING-01",
            "estimated_shipping": "2025-01-18",
            "priority_level": 3,
        },
    )
```

### 客户端使用

三层数据的访问方式：

```python
result = await client.call_tool("create_order", {"item": "键盘", "quantity": 2})

# 第 1 层：文本（给 AI 看的，AI 用来生成自然语言回复）
print(result.content[0].text)
# → "订单已创建: ORD-12345, 总计 ¥199.8"
# AI 会说："您的订单已创建成功，订单号 ORD-12345，总计 199.8 元。"

# 第 2 层：结构化 JSON（给前端程序用的）
print(result.structured_content)
# → {"order_id": "ORD-12345", "status": "pending", "total": 199.8}
# 前端可以直接取 result.structured_content["order_id"] 渲染订单卡片

# 第 3 层：内部元数据（给后台系统用的，AI 看不到！）
print(result.meta)
# → {"internal_id": "INT-98765", "warehouse": "WH-BEIJING-01",
#     "estimated_shipping": "2025-01-18", "priority_level": 3}
# 后台系统用 warehouse 信息做物流调度
# ⚠️ 注意：这些信息不会传给 LLM，保护了内部数据
```

> **给老板看的一句话总结**：工具返回的数据分三层——AI 看第一层（回复用户），前端看第二层（渲染 UI），后台看第三层（内部调度），各取所需互不干扰。

## 十四、场景 14：CORS 配置 —— 浏览器端 MCP 客户端

### 🎯 业务场景

> **故事**：前端团队做了一个 Web 版 AI 聊天界面（跑在 `http://localhost:3000`），需要从浏览器里直接调用 MCP 服务器（跑在 `http://localhost:8000`）。但浏览器因为"同源策略"拒绝了跨域请求。需要在 MCP 服务器上配置 CORS。
>
> **直观理解**：浏览器有一个"安保策略"——如果你的网页在 A 地址，想请求 B 地址的数据，浏览器会先"打电话"问 B："有个从 A 来的请求，你允许吗？"如果 B 没有配置 CORS，浏览器就拒绝这个请求。就像快递公司的安检——如果收件地址没有在"白名单"里，快递不给寄。
>
> **解决的痛点**：让 Web 前端（浏览器）能直接调用 MCP 服务器，不被浏览器拦截。

### 代码

```python
from starlette.middleware.cors import CORSMiddleware
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("Browser-Friendly Server")

@mcp.tool()
def search(query: str) -> str:
    return f"Results for: {query}"

# 获取 Starlette 应用
starlette_app = mcp.streamable_http_app(
    stateless_http=True,
    json_response=True,
)

# 添加 CORS 中间件
app = CORSMiddleware(
    starlette_app,
    allow_origins=["http://localhost:3000", "https://myapp.com"],
    allow_methods=["GET", "POST", "DELETE", "OPTIONS"],
    allow_headers=["Content-Type", "Authorization", "Mcp-Session-Id"],
    # 关键：暴露 MCP Session ID 头
    expose_headers=["Mcp-Session-Id"],
    allow_credentials=True,
)

# 启动: uvicorn main:app --host 0.0.0.0 --port 8000
```

**要点**：
- `expose_headers=["Mcp-Session-Id"]` 是必须的——浏览器需要读取这个头来维持 MCP 会话
- `allow_methods` 必须包含 `DELETE`（用于关闭 MCP session）
- 生产环境**千万不要**使用 `allow_origins=["*"]`，必须白名单指定允许的域名

> **给老板看的一句话总结**：Web 前端现在可以直接调用 AI 工具了——配置了安全的跨域策略，只允许我们自己的网站访问。

## 十五、场景 15：安全传输 —— DNS 重绑定防护

### 🎯 业务场景

> **故事**：安全团队审计时发现：MCP 服务器绑定在 `127.0.0.1:8000`（只监听本地），但攻击者可以用"DNS 重绑定"技术——先让你的浏览器访问 `evil.example.com`（解析到攻击者的 IP），然后在 JS 里把 DNS 改为解析到 `127.0.0.1`，这样浏览器以为在访问 `evil.example.com`，实际请求发到了你本地的 MCP 服务器。
>
> **直观理解**：就像快递诈骗——
> - 骗子用一个假地址寄快递，快递公司以为是正常包裹，送到了你家
> - DNS 重绑定：攻击者用一个假域名，浏览器以为是正常网站，请求打到了你本机的 MCP 服务器
>
> `TransportSecuritySettings` 会检查 HTTP 请求的 `Host` 头和 `Origin` 头——如果不在白名单里，直接拒绝。就像门卫检查访客的证件——证件上的地址和实际来源不匹配，直接拦下。
>
> **解决的痛点**：防止恶意网站通过 DNS 重绑定攻击你的本地 MCP 服务器。

### 代码

```python
from mcp.server.mcpserver import MCPServer
from mcp.server.transport_security import TransportSecuritySettings

mcp = MCPServer("Secure Server")

@mcp.tool()
def sensitive_op(data: str) -> str:
    return f"processed: {data}"

if __name__ == "__main__":
    mcp.run(
        transport="streamable-http",
        host="127.0.0.1",
        port=8000,
        transport_security=TransportSecuritySettings(
            # 允许的 Host 头列表
            allowed_hosts=["localhost", "127.0.0.1"],
            # 允许的 Origin 列表（用于 CORS 检查）
            allowed_origins=["http://localhost:3000"],
        ),
    )
```

### 效果

安全防护的实际效果：

```
# ===== ✅ 合法请求（Host 在白名单中） =====
POST http://127.0.0.1:8000/mcp
Host: 127.0.0.1:8000              ← Host 头是 127.0.0.1，在白名单中
→ 200 OK                          ← 正常处理

# ===== ❌ DNS 重绑定攻击（Host 不在白名单中） =====
POST http://127.0.0.1:8000/mcp
Host: evil.example.com             ← 攻击者伪造的 Host 头
→ 403 Forbidden                    ← 被拦截！门卫发现证件不对 🛡️

# ===== ❌ 非法 Origin（跨域攻击） =====
POST http://127.0.0.1:8000/mcp
Host: 127.0.0.1:8000
Origin: http://evil.example.com    ← 来自恶意网站
→ 403 Forbidden                    ← 被拦截！来源不在白名单 🛡️
```

> **给老板看的一句话总结**：加了一道"防火墙"——只有我们自己的应用能访问 MCP 服务器，恶意网站的攻击会被自动拦截。

## 十六、架构模式总结

> 🎯 这一节帮你在面对不同需求时，快速做出技术选型决策。

### 层次架构

整个 MCP SDK 的架构就像一栋大楼——从顶层的用户界面到底层的网络传输，每层各司其职：

```
┌──────────────────────────────────────────────────┐
│                    客户端应用                       │  ← 用户接触的地方
│  (Claude Desktop / Web App / CLI / 自定义应用)       │
├──────────────────────────────────────────────────┤
│  Client (高层)  或  ClientSession (底层)            │  ← 开发者写代码的地方
│  └── ClientSessionGroup (多服务器聚合)              │
├──────────────────────────────────────────────────┤
│              传输层 (Transport)                     │  ← "电话线/网线"
│  stdio_client │ streamable_http_client │ sse_client │
├──────────────────────────────────────────────────┤
│              网络 / 进程管道                         │  ← 物理连接
├──────────────────────────────────────────────────┤
│              传输层 (Transport)                     │
│  stdio_server │ StreamableHTTP │ SSE               │
├──────────────────────────────────────────────────┤
│  MCPServer (高层)  或  Server (底层)                │  ← 服务端开发者写代码的地方
│  ├── Tool (工具)      → AI 的"手"，能做事          │
│  ├── Resource (资源)  → AI 的"眼"，能看数据         │
│  ├── Prompt (提示)    → AI 的"说明书"               │
│  ├── Context (上下文) → 进度条和日志                │
│  ├── Elicitation      → 向用户弹"确认框"            │
│  ├── Sampling         → 工具反向调用 AI              │
│  ├── Task (异步任务)  → 后台长时间运行              │
│  └── Auth (OAuth)     → 门禁系统                    │
└──────────────────────────────────────────────────┘
```

### 选型决策树

当你面对新需求时，按照这棵决策树快速做出选择：

```
你的需求是什么？
│
├── "我要快速开发几个 AI 工具" → MCPServer (高层装饰器 API)
│   │
│   ├── "给 Claude Desktop 用" → stdio 传输 (零配置，5 分钟上线)
│   │
│   ├── "部署到云上给团队用" → Streamable HTTP (stateless)
│   │   └── "要不要和现有 Web 服务合并？" → ASGI 挂载 (场景 6)
│   │
│   └── "需要实时推送进度" → Streamable HTTP (stateful + EventStore)
│       └── "网络可能不稳定？" → 加 EventStore (场景 8)
│
├── "我要完全控制请求处理" → Server (低层回调 API)
│   ├── "200+ 工具要分页" → on_list_tools + cursor (场景 9)
│   ├── "schema 要动态变" → 手写 input_schema/output_schema (场景 1)
│   └── "要加中间件逻辑" → 直接操作 read_stream/write_stream
│
├── "要加安全认证" → MCPServer + AuthSettings + TokenVerifier (场景 2-3)
│
├── "任务要跑很久" → Task 模式 (场景 4-5)
│   ├── "只需要轮询进度" → run_task + poll_task
│   └── "中途要跟用户确认" → task.elicit + task.create_message
│
├── "要连多个 MCP 服务器" → ClientSessionGroup (文档 2 场景 11)
│
└── "要在浏览器里调用" → CORS 配置 (场景 14) + DNS 防护 (场景 15)
```

> **给老板看的总结**：MCP SDK 就像一套乐高积木——简单需求拼几块就行（5 行代码），复杂需求可以拼出任何你想要的形状（OAuth、异步任务、多服务器聚合）。从原型到生产，一套 SDK 全覆盖。
